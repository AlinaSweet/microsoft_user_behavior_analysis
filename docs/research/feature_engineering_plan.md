# 当前五列数据的特征工程设计

这是后续实现方案，尚未生成特征表或计算质量统计。所有内部字段和产物使用 snake_case；原始文件保持不变。

## 1. 原始字段与分析字段

已核对原始 CSV 表头及前 5 行，并引用已有原始文件清单；没有在本步完成全量字段值审计。

| 实际字段 | 规划字段 | 处理约定 |
|---|---|---|
| user_id | user_id | 读取为字符串，保留前导零；模型词表仅从训练历史构建 |
| item_id | item_id | 读取为字符串，不把 ID 数值大小当连续特征 |
| item_category | category_id | 在新标准表中显式映射名称，保留原始字段来源 |
| behavior_type | behavior_type / behavior_code | 文档规定 1=浏览、2=收藏、3=加购、4=购买；第三步全量核对后再生成紧凑编码 |
| time | event_time | 原格式 YYYY-MM-DD HH；校验后解析。时区未知时保留未指定时区，不自行认定为 UTC |

清单位置：../../data/catalog/user_behavior_raw.json。文件大小 492,264,642 字节；内容指纹见该清单。本步仅据实际文件说明当前规模，任务文档中的用户数/商品数不作为本机已测结果。项目名称沿用任务文档，CSV 的平台归属仍需数据提供者确认。

## 2. 时间和可用性规则

预测截点为 `as_of_time = t`。长度 W 天的历史窗口严格为 `[t - W days, t)`；购买标签在 `[t, t + 7 days)` 内观察。下列特征只可从历史窗口计算，不能读取标签窗口。

- 只有小时级时间，不能声称知道分钟级转化耗时或同小时行为先后。
- 同小时行为采用时间桶或稳定技术排序；技术排序只保证可复现，不代表真实顺序。序列实验需要报告并列比例与敏感性。
- 用户最早出现时间只能代表“首次观测”，不能当作注册日期。数据起点之前的历史未知，需要 `history_coverage_days` 等覆盖信息。
- 没有历史的次数可以记 0，但“没有足够历史覆盖”与“确实 0 次”要区分；最近行为间隔缺失时保留缺失指示。
- 本步仅提出窗口 1/7/30 天；第三步确定全量时间范围后再决定哪些窗口可用，不能填造 30 天完整历史。

## 3. 规划特征字典

所有窗口均以 t 为右开端点。计数基于按业务规则清洗后的明细，ID 基于真实值；计数整数位宽在检查范围后决定，不能先压缩再接受溢出。

### 用户统计

| 特征 | 明确定义 | 主要目的 |
|---|---|---|
| user_event_count_1d | 过去 1 天该用户全部行为条数 | 近期活跃 |
| user_event_count_7d | 过去 7 天全部行为条数 | 活跃基线 |
| user_active_days_7d | 过去 7 天有行为的不同自然日数 | 活跃连续性参照 |
| user_buy_count_7d | 过去 7 天 behavior_type=4 的条数 | 购买频率 |
| user_cart_count_7d | 过去 7 天 behavior_type=3 的条数 | 加购强度 |
| user_recency_hours | t 减最近一次历史行为时间，换算小时 | 最近活跃距离 |
| user_category_diversity_7d | 过去 7 天不同 category_id 数 | 兴趣广度 |
| user_recent_activity_ratio | user_event_count_1d / (user_event_count_7d / 7 + 1) | 近期活跃变化，平滑项为待验证设计 |

### 商品统计

| 特征 | 明确定义 | 主要目的 |
|---|---|---|
| item_pv_count_7d | 商品过去 7 天浏览条数 | 可观测热度 |
| item_buy_count_7d | 商品过去 7 天购买条数 | 历史成交行为强度 |
| item_unique_users_7d | 商品过去 7 天有任意行为的不同用户数 | 交互覆盖 |
| item_buy_user_share_7d | 该商品买过的不同用户数 / 与其交互的不同用户数，分母 0 时缺失 | 观测用户购买占比，不能叫曝光转化率 |

### 用户与候选商品/类目

| 特征 | 明确定义 | 主要目的 |
|---|---|---|
| pair_pv_count_7d | 用户与候选商品过去 7 天浏览条数 | 重复关注 |
| pair_fav_count_7d | 用户与候选商品过去 7 天收藏条数 | 收藏意向 |
| pair_cart_count_7d | 用户与候选商品过去 7 天加购条数 | 加购意向 |
| pair_buy_count_30d | 用户与候选商品过去 30 天购买条数 | 历史复购信号，仅在窗口可用时生成 |
| pair_recency_hours | 距用户最近一次与该候选商品交互的小时数 | 候选相关最近性 |
| pair_active_days_7d | 该用户与候选商品过去 7 天交互的不同日数 | 持续关注 |
| user_category_event_share_7d | 用户在候选类目的行为条数 / 用户全部行为条数 | 候选类目偏好，分母 0 时缺失 |

### 时间与序列输入

| 特征 | 明确定义 | 主要目的 |
|---|---|---|
| hour_of_day | t 的小时，0 到 23；每日 00:00 截点时为常量，剔除 | 仅在多时段预测实验中可能有效 |
| day_of_week | t 的星期编号，约定周一为 0 | 周期差异 |
| seq_item_ids | t 前最近 L 条历史商品 ID | DIN/GRU/BST 的商品历史 |
| seq_category_ids | 与 seq_item_ids 对齐的类目序列 | 跨商品兴趣共享 |
| seq_behavior_types | 与商品序列对齐的行为编码 | 多行为扩展方案 |
| seq_gap_hours | 相邻时间桶或技术序列间的小时差，并保留并列标志 | 时间间隔，不能解释为精确先后 |
| sequence_length | 截断后的真实历史长度，不含 padding | mask 和分层评估 |

首版截点建议每天 00:00，小时级截点另做实验，详见 [实验方案](experiment_plan.md)。边界统计、类别映射与序列来源时间均只取 t 前可用信息。

以上共 26 个特征定义；主键、覆盖信息、未知 ID 和并列标志是额外管理字段。它们是实现候选，不承诺全部保留；在同一验证集上做消融和冗余筛选。

## 4. 特征表达与编码

- 传统模型先使用上述紧凑统计；LR 的尺度变换参数只从训练集拟合，树模型不机械套用同一标准化需求。
- 低基数类别使用明确词表或适当类别编码；高基数 ID 不生成稠密独热矩阵，未知类别设置独立回退值。
- Target Encoding 是有监督编码：不能在全数据上求购买率再切分。训练样本使用只看更早、且标签已成熟的时间折外编码；验证/测试仅用训练阶段可用映射。官方 cross fitting 说明强调防止过拟合，但其随机 K 折例子不能直接满足本任务的时间约束。[scikit-learn 官方示例](https://scikit-learn.org/stable/auto_examples/preprocessing/plot_target_encoder_cross_val.html)
- 序列长度 L、embedding 维度和稀有类别阈值均作为待调参数，padding 与 unknown ID 不混用，mask 排除 padding。

## 5. 当前不能直接构造的指标

| 缺失信息 | 不能直接得出的结论 | 目前可做的替代 |
|---|---|---|
| 曝光记录 | 真正 CTR、未点击曝光负例 | 对可观测候选对预测未来购买，说明候选范围 |
| 金额、单价、订单数量 | Monetary、GMV、客单价、真实金额 RFM | Recency/Frequency；购买行为次数只称代理指标 |
| 秒/分钟与真实事件序号 | 同小时精确路径、分钟级购买耗时 | 小时桶、并列记录和敏感性分析 |
| 商品内容/品牌/设备/用户画像 | 品牌或人口属性偏好、已知硬件/订阅类型 | 商品/类目匿名 ID 与可观测行为 |
| 账户创建、真实离开平台时间 | 精确生命周期、已证实流失 | 首次观测和距最近行为的统计，标为代理 |

浏览、收藏、加购、购买不一定逐项发生；全平台简单次数比不是严格路径漏斗。后续漏斗应明确同一用户/商品、时间窗口、唯一用户口径，并对同小时顺序未知单独处理。

## 6. 中间表准备方案

规划四类表：`user_daily_stats`、`item_daily_stats`、`user_item_daily_stats` 和 `user_behavior_sequences`。前三者以实体 ID 和日期为键预聚合；后续按 t 前的历史计算滚动特征。序列必须在用户内跨分区汇集或按可验证分区策略生成，不能只在每个 CSV 块内排序就声称获得完整历史。

单个日期适合做有限基数分区；不按高基数 user_id/item_id 每值建一个目录。实际分区数、文件大小与 skew 处理在第三、四步测量后确定。产物另存 data/interim 或 data/processed，并登记生成参数与 SHA-256。
