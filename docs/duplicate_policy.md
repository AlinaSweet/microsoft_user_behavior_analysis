# 重复值与高频记录的当前处理约定

确认日期：2026-10-24。用户已确认第二阶段采用全部有效原始记录作为主表，超过90条只标记，另保留四元组计数供比较。

## 当前执行口径

1. 原始 CSV 只读。已有 validated Parquet 保留全部通过结构、标识符、行为与时间校验的记录，作为第二阶段输入；当前共12,256,906条。
2. 用户小时键为 user_id 与完整日期小时；跨商品和行为类型相加。沿用源时间，不转换时区。
3. raw_record_count <= 90 保留；raw_record_count > 90 标记 pending_review。90本身包含在保留区间。
4. 标记不截断计数、不删除整小时、不自动剔除其中任何行为。
5. 四元组为 user_id、item_id、behavior_type、event_time。保存其出现次数，同时提供原始记录数和不同四元组数。
6. event_id 是源记录序号，不是平台事件编号或同小时真实先后。
7. 同小时相同字段不能证明重复采集；最终针对浏览、收藏、加购、购买的错误日志删除规则仍待证据。
8. 主分布仅纳入有记录的用户小时。所有已出现用户与完整小时网格的无记录组合只作补充描述，不混入主分母。

## 已核验的90条参考线

- 活跃用户小时：682,940。
- 不超过90条：667,512，累计占比97.7409%。
- 恰好90条：494。
- 超过90条：15,428，涉及1,956,008条记录、3,357名用户。
- 90不是P90；P90为45条。用户附件采用最近秩法，早期探索报告采用线性插值；本数据所列主要分位数数值一致，方法分别保留。
- 单四元组最多出现22次。用户小时最高862条，涉及258个商品。

## 数据版本与适用范围

- clean_v1/events、base_v1/events及其三张聚合表保留第一阶段原任务的四元组归并口径，作为历史验收和对照。
- data/catalog/validated_records_v1.json 指向第一阶段已保存的全部有效记录；第二阶段使用此输入，不回填旧版清洗计数。
- 第二阶段数据库的原始事实表以源记录序号为主键，业务四元组不设唯一约束。
- 高频标记与四元组对照放在独立分析表或视图中，不改变原始事实表。
- 未来若有真实事件编号、订单信息或采集说明，应生成新版本并比较影响，不覆盖历史结果。
