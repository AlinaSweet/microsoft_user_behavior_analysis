# 3.3 序列模型与 3.4 融合解释

两个实验使用 3.1 的三键成熟样本，截点依次为 2025-11-25、2025-12-02 和 2025-12-09。每条样本预测截点后七天内的同对购买。加载各分割时核对文件指纹、时间窗口、三键和标签，还核对序列及候选类目快照的最近事件早于截点。

## 3.3 序列建模

从已登记的历史 30 天用户序列中保留最近至多 20 个商品小时单元。每个单元包含商品、类目、行为集合、四种行为计数和距预测截点的小时龄。同小时边界的截断可能只保留部分商品。GRU 和 LSTM 对保留的同小时单元做均值汇聚，沿不同小时递推。DIN 用候选商品和类目的嵌入作为查询，经局部激活加权汇聚历史序列。多头变体额外拼接候选查询的四头注意力结果，两条路径均屏蔽填充位。 [DIN 原文](https://arxiv.org/abs/1706.06978)

训练候选和历史拟合商品与类目词表。商品按支持量及固定 ID 次序取前 12,000 个，填充和词表外编码分别保留。16 个历史比例沿用 3.2 的中位数填补和标准化方法，重新在完整训练集拟合。各分割先按用户共用序列存储，入模时按候选行索引读取。

每个模型使用同一份固定训练欠采样，保留全部正例。AdamW 初始学习率为 0.003，每轮乘 0.8，梯度范数上限为 2。每轮在固定验证子集监控 AUC，最多跑 7 轮，连续 2 轮未提高超过 0.0002 时早停。按训练负例保留比例校正原始 logit。各变体恢复监控最优的检查点后，在完整验证分割比较 AUC，并按验证 F1 确定阈值。保存网络权重和选型记录后才读取测试分割。

## 3.4 两层 Stacking

基模型使用 3.2 预设的逻辑回归、XGBoost 基线，以及独立训练的四头 DIN。这个 DIN 按固定架构和 5 轮训练在读取验证数据前保存。同一截点的验证用户按固定种子分为约 65% 的二层训练组和其余的决策组。基模型输出概率经裁剪后转为 logit，二层模型在第一组训练标准化逻辑回归。第二组比较三种单模型、等权平均和 Stacking，按 AUC 确定类型，按 F1 冻结阈值。

测试阶段重放 3.2 六列概率并核对主键。原生树模型计算在独立进程运行；这样 macOS 上 PyTorch 和 XGBoost 的线程运行库各自在独立进程初始化。用用户聚类配对自助法比较 Stacking 和验证决策组获选的单模型。

## 解释与诊断

逻辑回归报告训练标准化尺度上的系数及赔率倍数。XGBoost 调用原生 TreeSHAP。DIN 以训练行作经验背景，替换输入组并遍历 5 组的全部 32 个组合，得到分组介入式 SHAP。候选商品与类目保持一组，完整历史序列和填充掩码保持一组，其余三组是用户、对级和商品类目历史比例。两种方法均检查原始 logit 的加和误差。测试解释案例按标签均衡抽样，解释结果随被解释样本和训练背景而变。 [SHAP 原文](https://proceedings.neurips.cc/paper_files/paper/2017/hash/8a20a8621978632d76c43dfd28b67767-Abstract.html)

错误画像使用冻结阈值的四类混淆组和完整测试集。训练未见用户和商品以 11 月 25 日的训练候选为参照。长尾商品定义为只有 1 至 2 位训练候选用户的商品。训练未见的候选仍须满足测试截点前已有交互，结果适用于该候选范围。

## 本地运行

安装[锁定环境](reproduction.md)。已有本机 3.1、3.2 和第二阶段特征时，可复制 [配置](../configs/stage3_advanced.json)，为两个部分分别指定新的数据、报告和清单位置。

```bash
PYTHONPATH=src .venv/bin/python scripts/run_stage3_advanced.py --config .cache/stage3_advanced.json
```

Windows PowerShell

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe scripts\run_stage3_advanced.py --config .cache\stage3_advanced.json
```

`--phase deep` 生成深度模型和单模型报告。`--phase ensemble` 读取已完成的深度目录，运行融合和解释。模型、预处理器、词表和逐行预测保存在本地数据目录，路径与指纹见 [3.3 清单](../data/catalog/stage3_deep_v1.json) 和 [3.4 清单](../data/catalog/stage3_ensemble_v1.json)。
