## 交互与口径

日期、用户群、类目三项全局筛选会重新计算全部核心模块；点击类目或商品排名可下钻，重置返回默认。
用户分层先按所选日期内所有类目确定，之后筛类目/商品，避免选一个类目就改变用户分层含义。
低活跃为窗口内少于10个四元组，高活跃为至少50个；新近观测为首次出现不早于窗口末3天，不代表注册。
RF高价值/潜力/近期风险/沉睡为窗口内购买记录的代理分层，不能称金额RFM。
各表可按当前条件导出CSV；下钻ID和所有筛选参数均使用参数化SQL。

| 模块 | 实际分析 |
|---|---|
| 数据概览 | 原始/四元组记录、用户/商品/类目、购买占比与分层 |
| 用户时序 | 每日四行为、每日购买用户占比、星期×小时日均量和购买覆盖、对数活跃长尾、购买分布、类目偏好 |
| 商品类目 | 交互量/购买覆盖双排名、支持量门槛、类目长尾、商品四象限与下钻 |
| 转化与关联 | 成熟7天严格跨小时漏斗、直接购买替代路径、下一活跃小时多标签转移、用户/用户商品对两类未来标签 |

购买覆盖是同窗浏览与购买组合的交集比例，不保证行为顺序。
严格漏斗只认不同小时的可确认先后，起点必须有完整7天随访；同小时候选另报。
小时转移只统计24小时内下个观测活跃小时，一个小时可含多行为，行和可能超过100%；不是退出率。
未来7天不足时显示不可用，不把NULL填为0；用户买其他商品不能当作该候选商品正例。

## 验收与深入探索

全窗口、日期×人群×类目、单日、成熟截点、空结果均与未聚合原事件独立核对，差异0；
成熟对级正例与已验收标签一致。见[审计](../outputs/reports/stage2/eda_audit.json)。
[静态图](../outputs/reports/stage2/figures/)可直接分享；
[补充统计](../outputs/reports/stage2/tables/)包括活跃度标准化关联、RF代理、类目购买间隔/复购和冻结覆盖。

建议从“相近活跃度下的加购关联”“同类目且支持量充足的高浏览低覆盖商品”“不同历史区间的时段规律”继续探索。
观察关联不证明因果；没有曝光无法算CTR，没有订单无法算真实复购，没有会话与分钟秒无法算在线时长。
数据期没有法定节假日，保留工作日/周末比较并明确无法执行节假日实证对照。

## GitHub Pages在线发布

在线版提供17个完整数据预计算视图：全周期与成熟随访各1个、7类用户分层、3个周窗口和5个热门类目。
它们各自使用原始全量数据计算，切换时整页模块同步更新，未以抽样替代全量统计。
热力图行为、排名指标、用户/用户商品对关联目标可切换；6种统计表可下载CSV。
任意日期×分层×类目的重新组合及单商品下钻仅在本地查询版提供；在线版隐藏这些输入与点击提示。
未来标签不成熟时保持不可用；类目覆盖以完整数据中的8,916个类目为分母。
人均行为和人均购买均以当前筛选全部用户为分母；购买记录不解释为订单。
每日趋势以灰底标记周末，热门商品附类目，漏斗附相邻/累计通过率和对应分母。

已计算视图和SHA-256见[发布清单](../outputs/reports/dashboard_publication_20261117/manifest.json)。
构建时校验每个源文件指纹、筛选参数、行为与逐日记录合计，仅向_site复制页面、样式、脚本与聚合JSON。
历史eda_baseline和eda_mature_example直接引用现有报告，Git中不再存一套副本。
