# 第一阶段第三项：清洗规则与复现

处理用户提供的完整 CSV，按真实规模验收。项目文档中的“亿级”是设计场景，不表示已在本机执行一亿行。

## 当前版本说明

下述为已验收的cleaning_v1历史口径。2026-10-24起，第二阶段采用全部有效记录、超过90条只标记及四元组对照；详见 [当前策略](duplicate_policy.md)。validated目录保留全部有效源记录，clean_v1/events与base_v1继续供历史复核和对照。

## 复现命令

在仓库根目录执行：

    bash scripts/run_project.sh clean \
      --policy configs/cleaning.json \
      --output-dir data/interim/clean_v1 \
      --report-dir outputs/reports/stage1_step3

输出数据目录必须是新目录；重复运行应另取版本名称并指定对应报告目录。程序拒绝替换已有清洗数据。

## 流程和内存边界

1. 计算原 CSV 指纹，用标准 CSV 解析器逐记录核对结构和列数。结构不符时失败，防止静默丢字段。
2. Pandas 以 200,000 条为一块读取，源字段先用 Arrow 字符串，关闭自动 NA 映射，保留前导零和字面 ID。
3. 现有 Dask LocalCluster 并行校验，待处理任务数不超过 worker 数。内存限制和阈值仍取 configs/dask.yaml。
4. 合格/拒绝块写入新 Parquet，保留一开始为 1 的源记录序号 event_id。它不是精确事件发生顺序。
5. 按块写入磁盘 SQLite 唯一键关系，全局去重。数据库缓存限制 64 MiB，临时计算使用磁盘。
6. 计算完整质量画像、精确分位数和异常标记，导出 events，再完整读回比较行数与值指纹。
7. 源指纹变化、行数不守恒、导出不一致、必填值缺失、唯一性失败或观察到 worker 重启时，不登记成功。

接口参考：[Pandas read_csv](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html)、[Dask Futures](https://docs.dask.org/en/stable/futures.html)、[Python sqlite3](https://docs.python.org/3.12/library/sqlite3.html)。数据库写入使用参数绑定。运行依赖仍以本仓库锁文件为准。

## 业务规则

| 检查 | 处理 |
|---|---|
| 五列必填值为空/全空白 | 整行进入 rejected 并登记原因，不伪造 ID |
| 标识符包含空白或控制字符 | 拒绝，保留合法字符串和前导零 |
| 行为编码不为 1/2/3/4 | 拒绝；编码含义按任务文档，待提供者确认 |
| 时间形状错误或不是有效日历时间 | 拒绝，不把 2 月 30 日自动修正为其他日期 |
| 时间越过配置边界 | 拒绝；最大源时间取 cleaning.json，边界不含上界；不自行推定时区 |
| 用户/商品/行为/时间四元组重复且类目一致 | 全局保留源记录序号最小的一条，其余计入重复移除数 |
| 同四元组的类目冲突 | 该键全部记录隔离；validated 块保留所有合格原记录，供追溯与恢复 |
| 商品在不同事件中出现多个类目 | 计入一致性报告，不推测匿名类目的业务含义 |

时间输出为无时区 datetime。小时级四元组可能合并真实的同小时重复操作；这是原任务规定的分析口径。validated 块保留去重前记录，可用于后续口径敏感性分析。

## IQR/3σ 的实际处理

对去重后的每用户、每商品总行为次数分别计算完整分布：

- Q1/Q3 按排序后 (n−1)×p 线性插值。
- IQR 区间为 Q1−1.5×IQR 至 Q3+1.5×IQR。
- 3σ 区间为均值减/加 3 倍总体标准差。
- 保存异常实体、原次数、两种标记，另给 IQR 截尾诊断值 iqr_capped_count。

统计异常不足以证明机器人或错误。处理方式为分离标记、保留诊断值与复核依据；合法高活跃事件留在事件表。标识符的数字大小不参与异常判断。将来模型需要截尾时，只能从训练部分拟合，不能把本次全量诊断阈值回填历史预测特征。

## 报告与追溯

质量 JSON 包含源前后指纹、代码版本、规则指纹、逐块统计、完整分布、重复/冲突对账、异常阈值、各 Parquet 指纹和资源观察。RSS 在块/阶段边界以及等待 worker 时采样，可能漏掉瞬时峰值，只称观测峰值。

对账关系：

    输入 = 无效记录 + 去除的重复记录 + 冲突键全部记录 + 干净记录

逐值读回以统一字符串的 Pandas 64 位行哈希再做顺序 SHA-256，与数据库结果比较。这是工程一致性检查，不声称数学上绝无碰撞；实际文件另存 SHA-256。

.cache/cleaning 数据库用于全局去重。第二阶段仍要建立规定的主表、维表、索引和查询接口。来源/许可的真实性不能由数值清洗证明，应由提供者补充。
