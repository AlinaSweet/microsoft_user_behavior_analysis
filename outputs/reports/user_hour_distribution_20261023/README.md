# 同一用户每小时操作记录数分布

分析日期：2026-10-23。

## 统计口径

- 输入为原始 user_behavior.csv 全量，不使用先前去重后的事件表。
- 变量 k：同一 user_id 在同一完整日期小时内的原始记录条数，跨商品、跨行为类型相加，重复行保留。
- 主分布仅纳入 k ≥ 1 的活跃用户小时。每个用户小时等权；同一用户可贡献多个小时样本。
- 沿用源文件的小时值，不做时区转换。不同日期的同一钟点分别分组。
- “记录数”不等于已证实的真实操作数。高频不直接证明重复上报或机器人。
- 本次统计粒度与“同用户、同商品、同行为、同小时”的相同记录组不同。
- 分组区间宽度不等，柱高表示区间频率，不表示概率密度。
- 分位数按全部活跃用户小时的记录数采用 NumPy linear 插值计算，标准差采用总体口径。

## 对重复值课题的启示

54.67% 的活跃用户小时不超过 10 条记录，91.74% 不超过 50 条。均值高于中位数，分布有明显右侧长尾。

每小时超过 100 条记录的组合有 11,474 个，占活跃用户小时的 1.68%；这些组合包含 1,579,253 条原始记录，占原始记录的 12.88%。这可用于衡量审查范围，不构成删除规则。

下一步建议在每个用户小时内，同时统计：

1. 总记录数 X。
2. 不同“商品＋行为类型”组合数 U。
3. 每个相同组合的出现次数分布，并另查类目一致性。
4. X−U 所表示的“同键额外记录数”，明确其尚未被证实为错误日志。

例如，100 条记录分布在 90 个商品行为组合，与 100 条记录集中在同一个组合，值得采用不同的排查方式。两个情况都不能仅凭小时级字段确定哪些是真实重复操作。

本次仅完成分布统计，没有更改重复值处理规则。
